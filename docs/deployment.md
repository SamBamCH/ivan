# Deployment: two machines

The intended setup is a **producer** (the laptop: owns the history, the models, the DraftKings Chrome
profile, the odds-api key, the timers) and a **consumer** (the server at 192.168.1.59, ssh alias
`ivan-server`, checkout `/opt/ivan/app`, service user `ivan`) that runs the web UI for someone else on
the same slates. Each has its own SQLite file; the producer pushes one way.

```
laptop (producer)                                          server (consumer)
  NFL: overnight.py / sync_to_server.sh ──reference tables + models──► nfl_history.sqlite (its own working tables)
  NBA: desk Publish, nightly.py ──feed.publish + push (rsync)──────► data/feed/nba ──ivan-nba-pull.timer──► nba_history.sqlite
  user timers: ivan-nightly (NFL), ivan-nba-nightly, ivan-nba-archive
                                                             ivan-web (system unit): scripts/serve.py on the Tailscale IP:80
                                                                └── one site, one password: /nfl, /nba (the desk), /mma
                                                             cloudflared: https://nba.prattflix.com → the whole site
```

## The server

First-time setup, as your admin user on the server:

```bash
sudo apt install python3-venv sqlite3 rsync
git clone git@github.com:SamBamCH/ivan.git ~/ivan
sudo ~/ivan/deploy/harden_server.sh        # user ivan, checkout to /opt/ivan/app, venv from requirements-server.txt, the sandboxed unit, ufw rule
sudo -u ivan nano /opt/ivan/app/.env       # ODDS_API_KEY, IVAN_PASSWORD_HASH (scripts/password.py), IVAN_PUBLIC=1, IVAN_FEED_URL=file:///opt/ivan/app/data/feed
sudo loginctl enable-linger ivan           # user timers survive logout
```

Then from the laptop, with an ssh alias `ivan-server` for the service user:

```bash
scripts/nfl/sync_to_server.sh ivan-server            # NFL reference tables + models
scripts/nba/feed.py push                             # NBA feed (IVAN_FEED_PUSH=ivan-server:/opt/ivan/app/data/feed in .env)
ssh ivan-server /opt/ivan/app/deploy/setup_nba_server.sh   # NBA dirs, schema, first pull, the pull timer, restart ivan-web
```

`requirements-server.txt` is generated by `deploy/derive_server_requirements.py` from what the NFL
pre-lock path, the web UI, the NBA desk and the feed import: no Selenium, no training extras.

### The unit

`deploy/ivan-web.service` (rendered by `install_unit.sh`) runs `scripts/serve.py --host <tailscale ip>
--port 80` as user `ivan` (the one UI, every sport; [web/README.md](web/README.md)): read-only system, writable only under `data/` and its cache, no new privileges,
private tmp, a system-call filter, the single capability to bind port 80. `Restart=always`. Jobs the UI
launches are `nice`d by the runner. `journalctl -u ivan-web -f` is the log.

### Access

- **One password** for the whole site (`IVAN_PASSWORD_HASH`, `scripts/password.py --set`; the login page at
  `/login`). With `IVAN_PUBLIC=1`, or through the tunnel, the site refuses to serve without one.
- **Tailnet**: `ufw` allows port 80 on `tailscale0` alone; invite people in the Tailscale admin console.
  `http://ivan.prattflix.com` is a public A record pointing at the Tailscale IP (resolves everywhere, routes
  only on the tailnet; on the home LAN the Pi-hole wildcard needs a local override).
- **Internet**: the Cloudflare tunnel (`sudo deploy/setup_cloudflare_tunnel.sh [hostname]`: installs
  cloudflared, creates the tunnel, writes `/etc/cloudflared/config.yml` from
  `deploy/cloudflared/config.yml.template`, refuses to finish without a password hash and `IVAN_PUBLIC=1`)
  forwards the **whole site** since 2026-10-30 (a tunnel set up before then forwards `/nba` only until the
  config is re-rendered on the server). Cloudflare caches by URL: the desk's CSV exports send `no-store`; a
  bypass-cache rule for the hostname is recommended.

## Pushing code

```bash
deploy/push.sh [ivan-server]     # rsync the working tree (not git; minus venv, data, .env) → bootstrap (deps, dirs, new tables) → kill the main pid → wait → curl 200
```

It restarts `ivan-web`, which drops any running job and the desk's in-memory state. Push between
slates. The server runs whatever the laptop's working tree holds, committed or not.

## Keeping data in sync

**NFL** (`scripts/nfl/sync_to_server.sh`, run by `overnight.py` when `IVAN_SYNC_HOST` is set): a
`VACUUM INTO` snapshot, every table except the working set (`nfl_player`, `odds`, `projection_snapshot`,
`lineup`, `lineup_simulation_results`, `contest_sim_report`), gzipped (~24 MB), loaded by
`scripts/nfl/import_reference.sh` drop-and-replace per table, plus `data/nfl/models/` by rsync. Safe while
someone is mid-slate on the server; if the import cannot get the lock in 30 s it fails loudly, re-run.

**NBA** (`ivan.core.feed`): the live bundle on every desk Publish and every autopilot tick, the reference
bundle every nightly; the consumer's pull timer applies them every 5 minutes and its desk's Refresh
pulls at once. The manifest carries a producer note (desk | autopilot | nightly, the autopilot switch,
the last tick) that the consumer's header shows. Table lists and the consumer's layering of its
own edits are in [nba/overnight.md](nba/overnight.md). `scripts/nba/consumer_check.py` drives the
consumer's desk from the producer (through the tunnel or the tailnet) and checks the round trip. `ivan-feed.service` (`deploy/install_nba_timers.sh
--feed`) serves the bundles over HTTP on the Tailscale address for a consumer that cannot receive rsync.

## Timers on the producer

| Unit | Sport | Schedule | Install |
|---|---|---|---|
| `ivan-nightly.timer` | NFL | 06:30, 12:30, 18:30, persistent | `deploy/install_nightly_timer.sh [--run-now]` |
| `ivan-nba-nightly.timer` | NBA | 06:45, 12:45, 18:45, persistent | `deploy/install_nba_timers.sh` |
| `ivan-nba-archive.timer` | NBA | every 5 min, 09:00–23:59 | same |
| `ivan-nba-capture.timer` | NBA | every 15 min, 09:00–23:45; acts only with the autopilot switch on (`scripts/nba/autopilot.py`) | same |

All are **user** units rendered with this checkout's path. The NFL nightly needs the desktop session's
display for the DraftKings scrape (`PassEnvironment=DISPLAY ...`). Both nightly jobs are idempotent and
catch up after sleep. Because the live timers and the laptop's `serve.py` processes run from the working
tree, **the checkout must stay on `master`**: a review branch left checked out broke the desk and the
archive timer for two days in October 2026.

## Where things are on the server

| | |
|---|---|
| `/opt/ivan/app/data/<sport>/<sport>_history.sqlite` | the server's databases |
| `/opt/ivan/app/data/nfl/input/web/`, `output/web/`, `jobs/` | NFL uploads, outputs, job logs |
| `/opt/ivan/app/data/feed/nba/`, `data/feed-state/` | what the laptop pushed; what was last applied |
| `/opt/ivan/app/data/nba/input/published/` | the laptop's pins and grids as the base layer |
| `journalctl -u ivan-web`, `journalctl --user -u ivan-nba-pull` | logs |

## Sizing

CPU-bound and forking: `config/nfl.json → classic.lineup_generation.n_jobs`, the generate step's
worker count, `sim` sizes. The NFL classic models are ~280 MB each and load per worker; 16 GB is
comfortable. Jobs run under `nice`, so other services on the box stay responsive.

## A sandbox consumer on the server

`deploy/sandbox_server.sh up` puts a second copy of this tree at `/opt/ivan/sandbox/app` on the server in
consumer mode (its own `data/`, `.env` with `IVAN_FEED_URL` pointing at the **same** `/opt/ivan/app/data/feed`
the laptop pushes to, password `sandbox`, the consumer limits) and runs it as the `ivan` user's unit
`ivan-sandbox` on `127.0.0.1:8002`, sharing the production venv (`PYTHONPATH=src` makes the sandbox's own
code win over the editable install). Reach it over an ssh tunnel: `ssh -f -N -L 8002:127.0.0.1:8002 ivan-server`,
then `http://127.0.0.1:8002/nba/`. Every route the brother's desk takes is real except the Cloudflare tunnel
and his login: your Publish or the autopilot tick pushes by rsync, the sandbox's Refresh pulls from the
server's disk, the same server-side code serves it under `/nba`. Break it freely; his desk and data are
untouched. `status`, `pull` (what his 5-minute timer does), `reset` (wipe the sandbox's own edits and
lineups) and `down` are the other actions; `scripts/nba/consumer_check.py --sandbox --refresh` checks it the
way it checks his desk.
